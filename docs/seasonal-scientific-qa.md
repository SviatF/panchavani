# PANCHAVANI — Seasonal Scientific QA and Release Governance (Wave 3)

**Implementation date: 2026-10-14.** This is NOT full validation of Hindu festival,
ritual or Muhurat calendars. Publication is still disabled, and public HTML
remains noindex while scientific and editorial review is unfinished.

## Automated validation added

The weekly `.github/workflows/seasonal-qa.yml` run, also triggered by
relevant code changes, checks a **48-case matrix**: the eight pilot cities
against six deliberately selected reference civil dates (2024 leap day,
2025 March/September equinoxes, June/December solstices,
and 2026-10-13 existing external comparator pilot).

All numerical results use a SHA-256-pinned NASA/JPL DE440s ephemeris, Skyfield,
a documented upper-limb sunrise convention, and a **provisional unapproved**
Lahiri-equivalent research model. The QA validates:

- city-local sunrise date and solar ordering;
- partition coverage with no gaps/skipped numbering for Tithi, Karana,
  Nakshatra and Nitya Yoga;
- residual at every complete phase transition (<= 2 arcseconds);
- two independently sampled root searches (30-minute vs 11-minute steps,
  <= 1 second drift) on Delhi and Chennai for all six date cases;
- Tithi transition vs corresponding half-Tithi Karana transition consistency;
- identical absolute UTC times for identical geocentric crossings observed
  in multiple city-day windows;
- exact input hash and automatically generated review blocking reasons.

**Methodological caveat:** both numerical searches use the SAME Skyfield/JPL
inputs and same Lahiri research convention. This tests numerical correctness,
NOT scientific independence from another ephemeris or Panchang methodology.
The seasonal dates, city positions and event conventions need stronger external
validation before factual data can be trusted for publication.

## Release decision mechanism (not a deploy tool)

The `engine/panchavani/review_packet.py` module reads the complete
SHA-256-linked QA evidence and outputs a `seasonal-review-BLOCKED.json`
review packet: 48 scoped city-days; source digest; unresolved scientific,
city-geodata, ritual and editorial evidence requirements. It refuses
to process unblocked/approved research records, does not sign approvals,
and cannot grant indexing or publication.

This is a *review packet*, not a production release manifest.
Future promotion requires independently reviewed and cryptographically
authenticated approvals; no publication/SEO route can consume this packet.

## SEO uniqueness and spam resistance

`engine/panchavani/seo_review.py` remains a preflight control for duplicate
location-body text, city/date canonical URLs and missing local evidence.
It is insufficient by itself to guarantee original value or Google ranking.
No automatic city-day SEO pages are generated by this QA or by nightly research.
Existing static site remains noindex. City-specific content and localized
calendar data must be factual, useful, substantively reviewed, and
consistent with the same global transition instants.
